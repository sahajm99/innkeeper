# Schema changes versus the course design

Every deviation from the course MySQL dump (`FinalDumpHotelManagementSystem.sql`) is listed here.
The new schema lives in `src/main/resources/db/migration/V1__schema.sql` and was run against H2 2.3
in PostgreSQL mode and PostgreSQL 16 before the first line of Java was written.

## Global changes

| Course | Innkeeper | Why |
|---|---|---|
| Mixed-case, inconsistent names (`RoomID`, `Branch_Name`, `ComplainID`, `maintenence_work`) | snake_case everywhere, spelling fixed (`maintenance_request`) | Predictable names; the JPA naming strategy maps 1:1. |
| Dates stored as `varchar(255)` (`booking_history.check_in`, `employee.Date_of_Birth`, `payment.payment_date`, `maintenence_work.scheduled_date`) | `DATE` for calendar days and `TIMESTAMP WITH TIME ZONE` for instants | Real date arithmetic and ordering in SQL; no `'May 5, 2024'` strings. |
| Money as `varchar(25)` (`fine.fine_amount`) or `decimal(10,0)` (`payment.amount`) | Money `NUMERIC(10,2)`; rates `NUMERIC(5,4)` | Cents matter; 8.25 percent must not become 8 percent. |
| No foreign keys at all (every `*_id` column is a bare int) | Foreign keys with explicit `ON DELETE` rules (RESTRICT for reference data, CASCADE for owned rows, SET NULL for optional links) | Referential integrity is the point of a database course. |
| Almost every column `DEFAULT NULL` | `NOT NULL` where the domain demands it (names, dates, statuses, rates) | The app never has to guess. |
| Free-text status columns | `CHECK (status IN (...))` constraints (all sets listed below) | Only known states exist. |
| Plaintext passwords in `login` | BCrypt hashes in `user_account.password_hash` | Never store secrets in the clear. |
| No unique constraints beyond primary keys | Unique: user_account username, booking confirmation code, complaint ticket, (branch, room number), (branch, inventory item name), (branch, team name), (branch, parking space), parking space booking, invoice booking, employee email, and (room, night) | Duplicates were possible everywhere. |
| `int AUTO_INCREMENT` | `BIGINT GENERATED BY DEFAULT AS IDENTITY`; the seed never inserts explicit ids | Standard SQL on PostgreSQL and H2; PostgreSQL identity sequences stay in step. |
| No optimistic locking | `booking.version` with `@Version` | Two staff acting on one booking cannot silently overwrite each other. |

## Table by table

| Course table | Innkeeper table(s) | Change |
|---|---|---|
| `branch` (`Branch_Name`, `Location`, `Phone_Number`, `branch_inventory_id`) | `branch` (code, name, tagline, description, address_line, city, state, postal_code, phone, email, tax_rate, timezone) | Structured address; per-branch tax rate and timezone drive invoice and check-in rules; dropped `branch_inventory_id` (inventory rows point at the branch, not the other way round). |
| `room` (`RoomID`, `RoomType` varchar, `Status`) | `room` (branch_id, room_type_id, room_number, floor, nightly_rate, status, notes) + `room_type` (code, name, description, max_occupancy, bed_setup, sort_order) | Rooms belong to a branch; room type is a table instead of a string; nightly rate lives on the room instead of hard-coded 30/50/60 in Java; status is AVAILABLE / OUT_OF_SERVICE (occupancy is derived from bookings, not stored). |
| `room_booking` (phone, name, email, type, dates, `roomid`, `customer_id`) | `booking` (confirmation_code, room_id, guest_id, check_in_date, check_out_date, adults, children, special_requests, status, nightly_rate, cancellation_fee, version, timestamps) + `room_night` (room_id, night_date, booking_id, UNIQUE(room_id, night_date)) | Guest data is not duplicated on the booking; a real status lifecycle; `room_night` makes double booking impossible at the database level. The course checked overlap by room *type* and set the first room of that type Occupied, so two bookings could hold one room. |
| `booking_history` | `booking_event` (booking_id, event_type, occurred_at, actor, note) | An append-only audit log of every transition instead of a varchar copy taken at check-out. |
| `customer` (`ID` = SSN/State ID, `number`, name, gender, contact, country, email) | `guest` (first_name, last_name, email lower-cased and indexed, phone) | SSN / ID-number columns dropped entirely; gender and country dropped (not needed for a stay). Email is contact data, not identity, because it is never verified: each booking gets its own guest row. |
| `login` (username, plaintext password, role, customer_id, employee_id) | `user_account` (username UNIQUE, password_hash, role CHECK, display_name, employee_id UNIQUE nullable, enabled) | BCrypt; primary key; roles renamed from customer / employee / admin to GUEST / STAFF / MANAGER. |
| `role` | none | Role is a checked column on `user_account`; a two-row lookup table added nothing. |
| `employee` (name, DOB varchar, gender, phone, `ssn`, email, salary, role_name, job, branch_id) | `employee` (branch_id, first_name, last_name, email UNIQUE, position, hired_on DATE, active) | SSN, salary, gender and date of birth dropped (not needed by any flow and sensitive); role moved to `user_account`. |
| `fine` (amount varchar, date, customer_id) | `fine` (booking_id, reason, amount NUMERIC, issued_at, issued_by_employee_id) | Fines attach to the stay they were incurred on, with a reason and who issued them. |
| `payment` (amount, type, `payment_details` with full card numbers, date varchar, customer_id) | `payment` (invoice_id, amount, method CHECK, reference, paid_at, recorded_by_employee_id) | Card numbers are never stored; payments settle an invoice. |
| none | `invoice` (booking_id UNIQUE, tax_rate, room_subtotal, tax, fines, cancellation_fee, total, status, issued_at, updated_at) + `invoice_line` (invoice_id, line_order, kind, description, quantity, unit_amount, amount) | The course computed the price at check-out in Java and kept nothing; the invoice is now a record that snapshots the tax rate and checks that `total = room_subtotal + tax + fines + cancellation_fee`. |
| `complain` (`ComplainName`, description, phone, customer_id) | `complaint` (branch_id, booking_id, ticket_number UNIQUE, guest_name, guest_email, category CHECK, description, status CHECK, resolution_note, created_at, resolved_at) | Ties to a branch and optionally a booking; has a lifecycle instead of being write-only. |
| `maintenance_team` (name, email) | `maintenance_team` (branch_id, name, specialty, contact_email, UNIQUE(branch_id, name)) | Teams belong to a branch; the `0 = Not Assigned` sentinel row is replaced by a nullable foreign key. |
| `maintenence_work` (type, description, scheduled_date varchar, roomid, status varchar, team_id) | `maintenance_request` (branch_id, room_id, title, description, priority CHECK, status CHECK, team_id, reported_by, created_at, started_at, completed_at) | Spelling fixed; real timestamps; priority added; status values OPEN / IN_PROGRESS / DONE. |
| `inventory` (item_name, quantity, branch_id; duplicate item rows summed at read time) | `inventory_item` (branch_id, name, category, quantity, reorder_level, unit, updated_at, UNIQUE(branch_id, name)) | One row per item per branch; reorder level drives the low-stock list. |
| `parking` (space number, label) | `parking_space` (branch_id, space_number, kind CHECK (GUEST / STAFF), booking_id UNIQUE nullable, UNIQUE(branch_id, space_number)) | Spaces belong to a branch and can be assigned to a stay at check-in. |
| none | `app_metadata` (meta_key, meta_value, updated_at) | Records `seeded_at` and `last_reset_at` for the about page and the nightly reset. |

## Enumerations (every CHECK set)

| Column | Values |
|---|---|
| `room.status` | AVAILABLE, OUT_OF_SERVICE |
| `booking.status` | CONFIRMED, CHECKED_IN, CHECKED_OUT, CANCELLED |
| `invoice.status` | OPEN, PAID, VOID |
| `invoice_line.kind` | ROOM_NIGHTS, TAX, FINE, CANCELLATION_FEE |
| `payment.method` | CARD, CASH |
| `booking_event.event_type` | CREATED, CHECKED_IN, CHECKED_OUT, CANCELLED, FINE_ADDED, PAYMENT_RECORDED |
| `user_account.role` | GUEST, STAFF, MANAGER |
| `maintenance_request.priority` | LOW, NORMAL, URGENT |
| `maintenance_request.status` | OPEN, IN_PROGRESS, DONE |
| `parking_space.kind` | GUEST, STAFF |
| `complaint.category` | ROOM, SERVICE, NOISE, BILLING, OTHER |
| `complaint.status` | OPEN, IN_PROGRESS, RESOLVED |

Other checks: `check_out_date > check_in_date`; adults 1..8; children 0..8; nightly rates and
fine, payment and invoice-line quantities positive; cancellation fee, inventory quantity and
reorder level non-negative; tax rate in [0, 1); guest email equals its lower-cased form;
`invoice.total = room_subtotal + tax + fines + cancellation_fee`. Text columns are
`VARCHAR(n)`, never `TEXT` (H2 maps `TEXT` to CLOB, which fails Hibernate validation). Free-text
columns: `booking_event.actor` is a username or "guest"; `maintenance_request.reported_by` is a
name; `fine.reason` and `inventory_item.unit` are short text.

## Dropped on purpose

- `customer.ID` / `customer.number` (SSN or state ID), `employee.ssn`: nothing that looks like a
  national identifier is stored anywhere.
- `payment.payment_details`: no card numbers, expiry dates or cardholder names.
- `employee.salary`, `employee.gender`, `employee.date_of_birth`, `customer.gender`,
  `customer.country`: no flow needs them.
